# Review of `PREREG_v2.md` and `kit_v2/` (fresh reviewer, 2026-11-20)

**Verdict: freeze after fixes, not as is.** Five blockers. Re-check the fix diff with a fresh reviewer before tagging (L22). I opened no label or prediction table; prediction facts come from `gates/` and LOG.

## Blockers

**B1. G3 item 4' is decided by data already seen (P2). Blocks B3/B6 only, but cannot be amended once frozen.** At issue: "no evaluable pair has p < 0.01 / k"; "not to obtain a verdict". Its inputs exist and are summarised in `gates/G3_*.json`, so k = 5 and the threshold 0.002 are knowable. T1R-T2R is coupled in the authors' traces (R 0.60, n 18, p 0.001), not in ours (R 0.14, n 37). Reviewer estimate from the printed n/R, assuming von Mises offsets (`g3_item4_estimate.py`): typical p ≈ 0.007, below v1 4.7's own α 0.01, above 0.002. The Bonferroni choice plausibly turns a fail into a pass; where non-rejection means pass, a multiplicity correction only loosens the gate. It also ignores phase and coupling status (`G3_REPORT.md` proposed "coupling pattern consistent"). Fix: compute item 4' before the freeze and print it in PREREG, with the unadjusted-α and status-match results; name the stored inputs by hash; mark B3 "gate chosen with inputs known".

**B2. L3 and the audit it invokes disagree.** At issue: "Breach rule (replaces v1's)". L3 omits two kinds the frozen `audit_session` still reports (a dedicated-source fetch outside a dedicated session; a session without a transcript) and the URL-token rule, leaving open which governs. Frozen code keys on v1 family names (`pugliese_dedicated` in the audit and Chapman exclusion; `catalogue` in `FAMILY_ORDER`). `families_v2.json` uses `dedicated` and `driver_line_resources`, so v2 sessions would be misclassified unless a mapping is stated. Fix: restate both kinds, the token rule and v1's audit-timing rule in L3, and map v2 family names to the frozen keys.

**B3. Leak surface grew; isolation is still a denylist.** Predictions v1 were pushed publicly after labels v1 froze (HANDOFF_1 §1), so the inherited v1 §13 protects nothing; PREREG is silent. The banned list omits mirrors (Software Heritage, Sourcegraph, web.archive.org). Phrase hits in web results are reported, never excluded. Readers keep web tools, and the `families_v2.json` scopes injected into `PROMPT_READER` are v1 search text ("find it", "any other paper that…"), contradicting C1. Predictions v2's push time is unstated. Fix: web tools only for search sessions and one unreachable-source reader; reader scope = assigned sources; add the mirrors and tokens; a web result naming the repository, its owner or `smpuglie` voids the session; L13 also denies other sessions' `~/.claude/projects` folders and `/private/tmp`; push predictions v2 after labels v2 lock.

**B4. The atlas path cannot run on the "unchanged" frozen pipeline; eligibility is left to post-freeze code.** (a) The frozen collector validates `manc_type` against `type_list.csv`, so `LINE:<id>` fails. (b) `merge_passes` pairs readings by `exp_id` and drops records without a pass-2 quote check, but the two codings share no `exp_id` and no Phase B. Line-ID matching revives v1's key-collision blocker. (c) Mapped records keep `mapping_confidence` "low", so they are ineligible under frozen `eligible()` unless an unstated rule overwrites it: which atlas records count is decided later. (d) C4's `multi_dn` needs `other_cell_types` and conflicts with L10 "never overwritten". (e) `manc_type` is read once, undeclared. (f) Nobody is named to build `atlas_line_ids.csv` "as read from its source data", and L7 bars the orchestrator from opening papers. Fix: state the matching key and collision rule, Phase B, `mapping_confidence` = the map row's value, the other mapped types as `other_cell_types`, C4's precedence and the `LINE:` validation; declare the single-reading map; build the ID list from the kit's Cande rows or in the map session.

**B5. Gate conditions 3–4 can be settled after data (L11, S5).** The verification frame, draw and repeat policy are unstated. The verifier is shown the value it checks (`verify_sample.csv` has `front_leg_rhythm`). A sampled dedicated record cannot be opened and becomes `cannot_verify`. "All experiments read twice" leaves open how atlas codings, siblings, `not_found` and excluded sessions enter. L8 lacks the "neutral identifiers" promised for label-review finding 4, inflating kappa. Nothing says the review, verification or gate run once, or forbids further collection after a failed gate or pooling v1.1 with v2. Fix: frame = eligible non-dedicated final records by `exp_id`, `default_rng(20261203).choice(n, 30, replace=False)`; blind verifier, comparison by script; kappa = frozen `agreement()["primary_field_all_values"]` on the inputs v1 used; neutralise identifiers with a fixed word list; each step once; a failed gate ends collection; no pooling.
